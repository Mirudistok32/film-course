# Следующая задача по плану

Пользователь доделывает сайт по сессиям и экономит лимиты: **за один вызов — одна задача из таблиц плана**, доведённая до зелёных проверок. Потом остановиться и отчитаться.

## 1. Выбрать задачу

- Если аргумент — номер задачи (`$ARGUMENTS`), взять её из таблицы раздела 4 [IMPLEMENTATION_PLAN.md](../../../IMPLEMENTATION_PLAN.md).
- Иначе взять первую задачу таблицы раздела 4 «Оставшиеся задачи». В таблице только невыполненные задачи: сделанные удаляются, их итог — в коде и в разделе 2.
- Задача со статусом 🔄 — незаконченная работа прошлой сессии: продолжить её, а не начинать следующую.
- Если таблица пуста — сказать об этом и предложить финальную проверку (`/code-review`), ничего не начинать.

Одной строкой сообщить пользователю, какая задача взята, и поставить ей 🔄 в таблице плана.

## 2. Изучить перед тем, как писать код

- Строку задачи: файлы, зависимости, критерии приёмки, способ проверки.
- Разделы ТЗ [docs/film-course-spec.md](../../../docs/film-course-spec.md), на которые ссылается раздел 1 плана («Карта требований»), и «Принятые решения» (раздел 2) — решения заказчика важнее ТЗ.
- Блок «Что учесть» в «Передаче работы».
- Доменный слой `src/domain/` — селекторы и действия уже есть, логику в компонентах не дублировать.
- Готовые компоненты `src/components/` и иллюстрации `src/illustrations/` — переиспользовать, новые делать в том же стиле.

Если есть неясный или важный выбор, который не следует из ТЗ, плана и кода, спросить пользователя (AskUserQuestion) **до** реализации — он сам просил задавать вопросы. Мелочи решить по здравому смыслу и упомянуть в отчёте.

## 3. Правила проекта

- Vue 3 + TypeScript + Pinia, без бэкенда. Прогресс меняется только через `store.apply(change)` с функциями из `progress.actions.ts`; набор текста — режим `'debounced'`.
- Hash-роутер: ссылки только `RouterLink` с именованными маршрутами; **никаких `href="#id"`** (прокрутка через `scrollIntoView`), никаких абсолютных путей `/…` в `href`/`src`. Готовую страницу подключить в `src/router/index.ts` вместо `PlaceholderView`, указать `meta.title`.
- Стили — только токены из `src/styles/tokens.css`, обе темы («пергамент» и «кинозал»). Без бесконечных анимаций, движение отключается настройкой и `prefers-reduced-motion`. Иллюстрации — SVG в коде, без внешних картинок.
- Доступность (ТЗ §34): видимые подписи полей, статусы словами, полная работа с клавиатуры, `role="status"`/`aria-live` для сообщений, спойлеры только по действию.
- Мобильный (ТЗ §35): одна колонка на 390 px, без горизонтальной прокрутки, крупные поля и кнопки.
- Игровые элементы (XP, ранги, ачивки) скрываются при `settings.showGamification = false`.
- Тексты интерфейса и комментарии — по-русски, в тоне остального кода. Учебный контент не пересказывает сюжет и не содержит непроверенных фактов.
- Шрифты подключать только поднаборами cyrillic/latin в woff2 (`src/styles/fonts.css`): всё встраивается в один HTML.

## 4. Тесты и проверка

Новую логику покрыть юнит-тестами в `tests/unit/`. Затем всё должно пройти:

```bash
npx vue-tsc --build
npx eslint .
npx vitest run
npm run build
npm run shots            # или npm run shots -- <часть имени>, например film
```

`npm run shots` снимает `dist/index.html` по file:// в Chrome в двух видах: `light-desktop` (1280 px) и `dark-mobile` (390 px). Ошибки консоли и горизонтальную прокрутку скрипт выводит сам. Если новой страницы или нужного состояния нет в списке `PAGES` в [scripts/screenshots.mjs](../../../scripts/screenshots.mjs), добавить.

**Посмотреть скриншоты своей задачи** (`.screenshots/<страница>--light-desktop.png` и `--dark-mobile.png`) через Read и исправить то, что выглядит сломанным или неопрятным. «Шов» фона на высоте окна в полностраничном снимке — это фиксированное зерно плёнки, а не ошибка.

Если проверку починить не удаётся, задачу не считать выполненной: оставить 🔄 и описать проблему в плане и в отчёте.

## 5. Обновить план

В [IMPLEMENTATION_PLAN.md](../../../IMPLEMENTATION_PLAN.md):
- строку выполненной задачи **удалить** из таблицы раздела 4 (а не ставить ✅) — так план не разрастается и его не нужно перечитывать целиком; её долю прибавить к «Сделано ~N%» над таблицей и пересчитать «Осталось: N%» (сумма долей оставшихся строк);
- новые решения и отступления от ТЗ → таблица раздела 2;
- раздел «Передача работы» переписать под следующую сессию: дата и результаты проверок (числа тестов), что сделано в этой задаче (кратко, только то, что нужно следующей сессии), «Следующие шаги по порядку» без выполненного, «Что учесть» без устаревших пунктов.

Если задачу не удалось довести до зелёных проверок, строку не удалять.

## 6. Остановиться и отчитаться

Коротко и по-русски:
- что сделано;
- как проверено, с числами: тесты, скриншоты, консоль;
- что спорно или оставлено на потом;
- **прогресс в процентах** (просьба пользователя — всегда): сколько всего сделано и сколько осталось, по долям из таблицы раздела 4;
- какая задача следующая и её доля: «Дальше — задача N (название), ~K% проекта. Запустите `/next-step`».

Следующую задачу в том же вызове не начинать.
