Источник требований — [docs/film-course-spec.md](docs/film-course-spec.md) (ТЗ v1.0), каталог — [src/data/film-course-catalog.json](src/data/film-course-catalog.json), пример экспорта — [tests/fixtures/progress-v1-example.json](tests/fixtures/progress-v1-example.json).

## 2. Принятые решения и отступления от ТЗ

| Решение | Причина |
|---|---|
| **Vue 3 + Vite + TypeScript + Vue Router + Pinia** вместо Next.js/React | Прямое указание заказчика («вьюикс»), уточнено: Pinia — официальный преемник Vuex. SPA без SSR снимает риск hydration mismatch с `localStorage`. |
| **TypeScript 6.0**, не 7.0 | `typescript-eslint` поддерживает TS < 6.1. |
| **Дизайн: «пергамент» + «кинозал»**, кинематограф + старое аниме + графика Артура Рэкхема | Прямое указание заказчика; заменяет «спокойный редакционный журнал» из §33, но сохраняет его принципы: читаемость, сдержанность, никаких бесконечных анимаций. |
| **Пастельная палитра** (сессия 13): шесть оттенков `--tint-*` + `--tint-*-ink` в обеих темах; `data-tint` задаёт `--tint`/`--tint-ink` блоку. Оттенок уровня — по кругу (`domain/shared/tint.ts`): карта курса, шапки уровня и фильма, обложки, журнал; свои цвета у тем словаря и групп достижений. Сцена героя — пастельные сумерки, пройденные кадры полос прогресса «засвечены» пастелью | Заказчик: «не хватает пастельных цветов, дизайн плоский». Цвет только украшает — смысл передан текстом и формой (§34). Сброс прогресса остаётся киноварью — опасное действие. |
| **Шрифты из portfolio-v2**: Ubuntu (заголовки, 500/700), Roboto (текст, переменный), Tektur (`--font-accent`: подписи над заголовками, крошки, номера, цифры) вместо Cormorant Garamond и Literata; файлы и лицензии — `src/assets/fonts` | Прямое указание заказчика. У шрифтов нет курсива — курсив в интерфейсе убран, а не синтезирован. |
| **Иллюстрации — SVG, нарисованные в коде** (процедурные корявые деревья, эмблемы уровней, виньетки) | Никаких сторонних картинок и прав на изображения; страницы не зависят от загрузки внешних ресурсов (§32). |
| **Учебный контент для всех 100 фильмов** написан как редакционный черновик (`contentStatus` в документации) | Каталог содержит только `learningFocus`; MVP (§46) требует уникального фокуса, вопросов и упражнения у каждого фильма. Тексты оригинальные, без пересказа сюжета и без непроверенных фактов (стран, хронометража). |
| **Схема сохранения v2** (пример из ТЗ — v1) | Нужны: журнал XP-событий (защита от двойного начисления), общий список заметок (журнал + свободные заметки), мотивы, выпускная работа, расширенные настройки. v1 мигрируется автоматически, есть тест на файле-примере. |
| **XP = сумма уникальных событий** (`xpLedger`), поле `xp` хранится для читаемости и пересчитывается | §25: «XP нельзя просто сложить… предпочтительно хранить уникальные event IDs». |
| **Заметки — единый массив** `notes` с `filmId: string \| null` | Журнал объединяет все заметки, свободные заметки без фильма (§13, §27). |
| **Строгий порядок уровней — опция, по умолчанию выключена** | §10: не блокировать жёстко; в строгом режиме закрытые уровни открыты для чтения (режим обзора), но не для записи прогресса. |
| **Завершение фильма** — явная кнопка; условие: «посмотрел» + упражнение (в облегчённом режиме — наблюдение в цепочке) | §12.7, §19. |
| **Завершение уровня** — явная кнопка; критерии: ≥70% просмотров, ≥1 упражнение (облегч.: ≥1 содержательная запись), итоговая рефлексия уровня | §19. |
| **Выпускная работа** — отдельная страница `/graduation` | §6 ур. 13, ачивки «Аргумент, а не впечатление», «Собственная мысль», «Курс пройден». |
| **Объединение при конфликте текста** — текущая версия остаётся в поле, импортированная сохраняется отдельной заметкой с меткой `merge-conflict`; повторный импорт не плодит копии (дедупликация по тексту) | §25: «не терять молча». |
| **Перед заменой при импорте** — снимок текущего прогресса в `localStorage` + кнопка «Отменить импорт» и кнопка скачать копию | §25 п.6, §26. |
| **Аниме вплетено в уровни**, по одному фильму в 8 уровней: «Ещё вчера» (2), «Актриса тысячелетия» (4), «Сказание о принцессе Кагуя» (6), «Призрак в доспехах» (7), «Идеальная грусть» (9), «Унесённые призраками» (10), «Могила светлячков» (12), «Принцесса Мононоке» (13) | Выбор заказчика (сессия 2) вместо отдельного уровня: 13 уровней из ТЗ сохраняются, аниме сравнивается с игровым кино на том же навыке. Статус `proposed-expansion`, отмечено в `sourceNote`. |
| **Шапка не липкая** | §35: на телефоне липкая шапка съедает место над полем ответа и перекрывает содержание. Навигация доступна вверху страницы и через ссылку «Перейти к содержанию». |
| **Никаких якорных ссылок `href="#id"`** внутри страниц | Hash-роутер воспримет их как маршрут. Прокрутка к блоку — через `scrollIntoView`; ссылка «к содержанию» фокусирует `main` из обработчика. |
| **Перфорация плёнки — CSS-маска** (`mask` со скруглённым прямоугольником, цвет `--hero-hole`) | Картинка без внешних файлов, цвет отверстий меняется вместе с темой. |
| **Статус «предложенное расширение» на карте курса — одна сноска под плёнкой** («Уровни 3–13 — …»), а не метка на каждом кадре | Метка на 11 кадрах из 13 шумит; диапазон считается из `status` каталога. |
| **Запуск двойным кликом по `dist/index.html`** (file://, без сервера): hash-роутер (`/#/film/nosferatu`), вся сборка в одном HTML — JS, CSS и шрифты встроены (`vite.config.ts` + `scripts/postbuild.mjs`) | Прямое указание заказчика, как в соседних проектах (portfolio-v1/v2). С диска браузер не грузит модули и шрифты отдельными файлами (CORS). Hash-адреса работают и с диска, и на любом хостинге без перенаправлений. Заменяет прежнее решение «history-режим + 404.html». |
| **Ссылки со страницы уровня в словарь** — `/glossary?term=<id>` (термин) и `/glossary?level=<id>` (все термины уровня) | Словарь (6.6) должен понимать эти параметры: подсветить термин или отфильтровать по уровню. |
| **Пройденный уровень** — вместо списка условий печать и дата; итоговую заметку можно дополнять | Условия могли измениться после завершения (снятый просмотр, облегчённый режим) — «ещё нет» рядом с «пройден» сбивает. Завершение не отменяется (§10). |
| **Закрытый уровень (строгий порядок)** — итоговая заметка только для чтения, кнопки «Завершить» нет, кнопка продолжения ведёт к предыдущему уровню | §10: чтение не блокируется, запись — по порядку. |
| **Фильмы-дополнения на уровнях 1–2** помечены словом «предложение» в карточке + сноска; на уровнях 3–13 — одна сноска об уровне | Только на уровнях 1–2 фильмы из исходной концепции смешаны с предложенными. |
| **Страница фильма — три шага-вкладки** «Перед / Во время / После просмотра» (ARIA tabs, стрелки/Home/End); шаг в адресе `?step=`, по умолчанию — по статусу (`filmStartStage`), дальше сам не переключается. Заметки и итог — под вкладками всегда | Выбор заказчика (сессия 6): §12 «давать материал порциями». Смена только query не прокручивает страницу (`scrollBehavior` в роутере). |
| **Вопросы «после просмотра» (§12.4) — подсказки к полям цепочки**: наблюдение → «Я заметил…», эффект → «почувствовать/ожидать…», интерпретация → «Возможно, это означает…»; «На это указывает…» — общий вопрос. Примеры формы ответа — общие, не про конкретный фильм | Одни поля вместо двух наборов; пример не подсказывает трактовку фильма. «Другое прочтение» и «Открытый вопрос» — в раскрывающемся блоке «Пойти дальше». |
| **Самопроверка упражнения** = 3 общих вопроса из §12.5 (`COMMON_SELF_CHECK`) + свои `selfCheck` урока; в прогрессе — индексы в этом порядке. На прогресс не влияет | В контенте `selfCheck` есть только у одного урока. |
| **На странице фильма заметки только добавляются и удаляются** (с подтверждением); редактирование и поиск — в журнале, ссылка `/journal?film=<id>` | Журнал (6.5) должен понимать `?film=`. |
| **Фильм закрытого уровня (строгий порядок)** — только чтение, `openFilm` не вызывается | Как на странице уровня; «Продолжить» на главной не ведёт в закрытый уровень. |
| **Журнал — единая лента заметок и разборов** (разбор = ответы цепочки + ответ упражнения одного фильма), новые сверху по дате изменения. Разбор в журнале только читается, ссылка «Открыть разбор» → `/film/<id>?step=after` | Правка разбора в двух местах дала бы два редактора одних полей; заметки правятся на месте. |
| **Журнал: уровень, фильм и вкладка — в адресе** (`?level=`, `?film=<id>` или `?film=none` — свободные, `?tab=motifs`); поиск и тип записи — только на странице | Ссылка со страницы фильма и перезагрузка сохраняют фильтр; набор в поиске не засоряет историю. |
| **Поиск в журнале** — все слова запроса, без учёта регистра и «ё», по тексту, меткам, названию фильма и режиссёру | §13 «поиск по содержимому»; находить записи по фильму, даже если его нет в тексте. |
| **Шаблон записи** §13 — кнопка «Вставить шаблон» в форме заметки, а не обязательные поля | ТЗ: «писать свободно, без обязательной структуры». |
| **Мотив**: фильмы добавляются по одному через список с группами по уровням, а не сто чекбоксов | Удобно с клавиатуры и на телефоне. |
| **Словарь — по темам, а не по алфавиту** (7 тем: кадр и план, композиция и пространство, камера и взгляд, монтаж и время, свет/цвет/стиль, звук, смысл и напряжение); тема — поле `group` термина, порядок тем — `GLOSSARY_GROUPS` | Выбор заказчика (сессия 8): словарь читается как учебник; для быстрого поиска есть поле поиска и оглавление тем. |
| **Статьи словаря раскрыты целиком**; из уроков с термином видно 5, остальные — кнопкой «Ещё N»; при `?level=` уроки этого уровня первыми | Выбор заказчика (сессия 8). У некоторых терминов до 20 уроков. |
| **Пример в словаре, раскрывающий финал** (`example.spoiler`: «Стачка», «Пылающий»), скрыт под спойлером | §34: спойлеры только по действию. |
| **Достижения: значок — форма по группе** (печать, ромб, щит, восьмиугольник — `ACHIEVEMENT_GROUPS[*].figure`, компонент `AchievementSeal`), открытый — оттиск киноварью с датой, закрытый — пунктирный контур с подсказкой «Как получить»; над списком — легенда форм | §34: смысл не только цветом. Закрытые ачивки видны с условием, как критерии уровня (§19 «видеть критерии заранее»). |
| **При скрытых игровых элементах** страница достижений показывает объяснение и кнопку «Показать ранги и достижения»; блок «Активность» остаётся | Активность — учёт занятий (§20), а не награда. Награды продолжают считаться в фоне. |

| **Данные и настройки — одна страница** `/settings/data`: резервная копия, импорт, настройки, сброс, «О формате файла» | §8 п.7; настройки сохраняются вместе с прогрессом и попадают в копию — логично держать рядом. |
| **Импорт — предпросмотр таблицей «Сейчас в браузере / В файле»**, затем «Объединить» (основная кнопка) или «Заменить» (подтверждение с кнопкой «Скачать текущую копию»). | **Отмена сброса** — снимок `before-reset` можно вернуть кнопкой «Вернуть данные до сброса» (`store.undoReset`, общий `restoreSnapshot` с отменой импорта) | Снимок и так делался; без кнопки им нельзя было воспользоваться. |

## 3. Риски и пробелы

- **Контент — черновик.** Тексты уроков, образцы разбора и примеры словаря требуют редакторской проверки (этап 6 ТЗ). Уровни 3–13 — предложенное расширение (`status` в каталоге показывается в интерфейсе).
- **Поля `runtimeMinutes`, `country`, `originalTitle`** в каталоге пусты — не показываются, пока не заполнены и не проверены.
- **`localStorage` ограничен** (~5 МБ) и привязан к браузеру — экспорт JSON является основным способом защиты (напоминания, кнопка на главной).
- **Несколько вкладок** одновременно: реализована синхронизация через событие `storage`; при одновременном редактировании в двух вкладках побеждает последняя запись (задокументировано).
- **Автоопределение «формальных решений»** в заметках (ачивка «Не только сюжет») — эвристика по словарю киноприёмов; ошибка возможна, но не влияет на прогресс.
