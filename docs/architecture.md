# Архитектура

Одностраничное приложение без бэкенда. Всё, что знает сайт, — каталог курса в коде и прогресс пользователя в `localStorage`.

```
src/
  data/           film-course-catalog.json — каталог: уровни, фильмы, статусы источника
  content/        учебные тексты: уроки по уровням (lessons/level-NN.ts), лекции уровней, словарь;
                  course.ts собирает из них объект Course
  domain/         чистая логика без Vue и DOM — её покрывают юнит-тесты
    catalog/      типы курса, сборка Course, проверка согласованности каталога и контента, словарь
    progress/     типы прогресса, действия, селекторы, журнал, хранение, импорт/экспорт,
                  объединение, миграции, валидация
    rewards/      XP, ранги, достижения (конфиг и движок)
    shared/       даты, id, поиск по тексту, пастельный оттенок уровня
  stores/         progress.ts — единственный Pinia-стор: состояние, автосохранение, награды, уведомления
  composables/    тема и размер текста, заголовок страницы, прокрутка к блоку
  components/     общие компоненты интерфейса (поля, кнопки, статусы, диалог, шапка AppShell)
  illustrations/  SVG, нарисованные в коде: дерево, сцена героя, эмблемы уровней, печати, виньетки
  views/          страницы
  router/         маршруты
  styles/         токены, шрифты, базовые стили
```

## Поток данных

1. **Каталог.** `content/course.ts` собирает `Course` из JSON-каталога и текстов (`buildCourse`). `catalog.validate.ts` проверяет, что у каждого фильма есть урок, термины словаря существуют, упражнения покрывают нужные теги; тест `catalog.test.ts` падает при расхождении.
2. **Прогресс меняется только через стор.** Компонент вызывает `store.apply(change)`, где `change` — чистая функция из `progress.actions.ts` вида `(progress, now) => progress`. Стор:
   - сразу кладёт новое состояние (интерфейс реагирует мгновенно);
   - в режиме `'immediate'` тут же пересчитывает награды (`evaluateRewards`) и пишет в хранилище;
   - в режиме `'debounced'` (набор текста) делает то же через 400 мс паузы. Перед уходом со страницы (`pagehide`, скрытие вкладки) отложенная запись сбрасывается.
3. **Чтение — селекторы.** Статусы фильмов и уровней, критерии завершения, статистика, лента журнала считаются в `progress.selectors.ts` и `progress.journal.ts`; компоненты логику не дублируют.
4. **Награды** не хранят «флаги»: XP — сумма уникальных событий `xpLedger`, достижения выдаются один раз по id. Повторное действие или повторный импорт ничего не начисляют.
5. **Индикатор сохранения** (`SaveIndicator`) показывает `pending / saved / error`. Ошибка записи (переполнение, запрет хранилища) не теряет введённое: состояние остаётся в памяти, пользователь видит сообщение и может скачать копию.
6. **Несколько вкладок.** Событие `storage` подтягивает данные из другой вкладки, если в текущей нет несохранённого ввода.

Формат данных, миграции, импорт и объединение — в [save-format.md](save-format.md).

## Маршруты

Hash-режим (`createWebHashHistory`): адреса вида `index.html#/film/nosferatu` работают и с диска, и на любом хостинге.

| Путь | Страница |
|---|---|
| `/` | Главная: продолжить, путь, последние записи, резервная копия |
| `/course` | Карта 13 уровней |
| `/course/:levelId` | Уровень: лекция, фильмы, термины, завершение |
| `/film/:filmId?step=before\|during\|after` | Урок фильма тремя шагами |
| `/journal?level=&film=&tab=motifs` | Журнал заметок и разборов, мотивы |
| `/glossary?term=&level=` | Словарь по темам |
| `/achievements` | Ранги, опыт, достижения, активность |
| `/graduation` | Выпускная работа |
| `/settings/data` | Резервная копия, импорт, настройки, сброс |

Правила: ссылки — только `RouterLink` с именованными маршрутами; никаких `href="#id"` (hash-роутер примет их за маршрут) — прокрутка к блоку через `useScrollTo`/`scrollIntoView`; никаких абсолютных путей `/…` в `href` и `src`. Заголовок вкладки — `meta.title` маршрута.

## Стили и оформление

- **Токены** — `src/styles/tokens.css`, две темы: светлая «пергамент» и тёмная «кинозал». Тема — `data-theme` на `<html>` (выбор пользователя) или системная настройка. Компоненты используют только токены.
- **Пастель.** Шесть оттенков `--tint-rose … --tint-lavender` с парными `--tint-*-ink` для текста и линий поверх заливки. Атрибут `data-tint` на любом блоке задаёт `--tint` / `--tint-ink` для него и вложенных элементов (`base.css`). У каждого уровня свой оттенок по кругу (`domain/shared/tint.ts`): карта курса, шапки уровня и фильма, обложки, записи журнала. Темы словаря и группы достижений тоже окрашены. Цвет только украшает — смысл всегда передан текстом или формой значка.
- **Шрифты** — `src/styles/fonts.css`: Ubuntu (заголовки), Roboto (текст), Tektur (подписи над заголовками, метки, цифры; переменная `--font-accent`). Только woff2 с кириллицей и латиницей — они встраиваются в HTML.
- **Движение.** Без бесконечных анимаций; переходы отключаются системной настройкой `prefers-reduced-motion` и настройкой сайта (`data-reduced-motion`). Зерно плёнки — неподвижный слой поверх страницы.
- **Мобильный.** Одна колонка на 390 px, кнопки и поля не меньше 2.75rem, шапка не липкая.

## Сборка в один файл

Браузер не загружает с диска модули и шрифты отдельными файлами (CORS для `file://`), поэтому:

- `vite.config.ts`: `base: './'`, один JS-чанк, один CSS, все ассеты встраиваются как `data:`;
- `scripts/postbuild.mjs` вкладывает JS и CSS в `dist/index.html` и удаляет `dist/assets`. Если что-то не встроилось, сборка падает.

## Тесты

- `tests/unit/` — домен: действия, селекторы, журнал, награды, импорт/экспорт, объединение, миграция примера v1 (`tests/fixtures/progress-v1-example.json`), каталог и словарь, компоненты.
- `e2e/` — Playwright по `file://` собранного `dist/index.html` в Chrome: прохождение фильма с перезагрузкой, шаг урока в адресе, экспорт → сброс → импорт, повреждённый файл и повреждённые данные в браузере, страницы и меню на телефоне. Помощники — `e2e/helpers.ts`.
- `scripts/screenshots.mjs` — снимки всех страниц и состояний (`PAGES`) для визуальной проверки; новое состояние страницы добавляется в этот список.
